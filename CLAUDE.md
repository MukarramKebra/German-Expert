# German Expert — Project Notes

Static e-commerce site for **German Expert**, a German car-parts shop in Sharjah, UAE (Mercedes-Benz, BMW, Audi, VW, Porsche, MINI, Opel). Hosted on GitHub Pages at `https://mukarramkebra.github.io/German-Expert/` (repo `MukarramKebra/German-Expert`), backed by Supabase. No build step, no `package.json` — plain HTML/CSS/JS.

Forked on 2026-11-08 from the Expert Hardware Kuwait store (repo `MukarramKebra/Hardware-Website`, git remote `kuwait` here, Supabase `qhebhvllkovfbkqrcnmm`). That project is a separate live site — never write to it from here. Many internal identifiers still carry the fork's names on purpose (table prefix `expert_*`, localStorage keys `jain_*`/`bahar_*`, CSS token `--orange`); they're invisible to visitors and renaming them is pure churn.

## Architecture

- **Storefront**: `index.html`. CSS/JS are injected at runtime by two small loader IIFEs (near the top and bottom of `index.html`) that build `code/css/*.css?v=<version>` / `code/js/*.js?v=<version>` tags. The version comes from `localStorage.expert_asset_v`, synced against `expert_settings.asset_version` (bumped by the admin's "Flush Cache" button, not by git pushes).
- **Single config point**: top of `code/js/01-config-data.js` — `GE_SB_URL`, `GE_SB_KEY_B64` (base64 publishable key; the public key, not a secret), `SHOP_WA` (WhatsApp number used for every wa.me link), `SITE_URL`, `CURRENCY` + `fmtPrice()` / `roundMoney()` (AED, 2 decimals — every storefront price goes through `fmtPrice`). `scripts/generate-product-pages.js` parses `GE_SB_URL`/`GE_SB_KEY_B64` out of that file with a regex, so keep them simple string literals. Two other places hardcode the project and must be kept in sync: `admin/js/01-core-data.js` (`SB_URL`/`SB_KEY`) and `order-invoice.html` (`SB_URL`).
- **Admin panel**: `admin/index.html` + `admin/css/` + `admin/js/` — separate static app. `admin/index.html` has `<base href="../">`, so relative URLs resolve from the SITE ROOT (write `logo.svg`, never `../logo.svg`).
- **Product pages**: `/product/<slug>.html` + `sitemap.xml` are AUTO-GENERATED by `scripts/generate-product-pages.js` from live Supabase data via `.github/workflows/generate-seo.yml` (every push to `main` except pushes touching only `product/**`/`sitemap.xml`, plus nightly 03:17 UTC). Never hand-edit them. `MIN_PRODUCTS` defaults to 0 because the catalog starts empty — raise it (or set `SEO_MIN_PRODUCTS` in the workflow) once there's a real catalog, so an outage returning `[]` can't wipe the sitemap.
- **Backend**: Supabase project `qljcyiwkwdfodmabnzol`. **`supabase/schema.sql` is the source of truth** for every table, function, RLS policy and grant (rebuilt from the Kuwait live DB, not its stale SQL files). Tables: `expert_*` (catalog/site/orders/admin) and `offer_*` (email subscribers/campaigns). Any schema change: update `schema.sql` too.
- **Admin auth**: real Supabase Auth users. `doLogin()` in `admin/js/03-auth.js` derives `<username>@german-expert.internal` (`EMAIL_DOMAIN`, must match `supabase/functions/admin-manage-accounts`) and calls `/auth/v1/token?grant_type=password`. RLS on every admin-write table only allows `authenticated` + `is_admin(auth.uid())` (a row in `expert_admin_profiles`); anon can only `select`. Accounts are created/edited/deleted ONLY via the `admin-manage-accounts` Edge Function (service role). Its `bootstrap` action creates the first accounts and only works while `expert_admin_profiles` is empty. After login, `SB_HDRS.Authorization` (`admin/js/01-core-data.js`) is mutated in place to the user's token — that's what authenticates every admin write. Checkout stock deduction uses the `decrement_stock` RPC (anon-callable, can only subtract).
- **Edge functions** (`supabase/functions/`): `admin-manage-accounts`, `notify-order` + `order-invoice` (deploy with JWT verification OFF), `send-offers`, `unsubscribe`. Email goes through Resend — needs `RESEND_API_KEY`; `OWNER_EMAIL` / `FROM_EMAIL` secrets override the placeholder addresses. The send-offers cron token lives in `expert_service_secrets` (key `send_offers_cron_token`).
- **Hero showcase**: `#showcase` (top of `index.html`) = `code/js/08-hero.js` + `code/css/10-hero.css`. Background is a WebGPU shader (`shaders@4.0.5` via jsDelivr ESM, `HERO_SHADER_PRESET`; check prop names against `~/.claude/skills/shaders/components.md` / shaders.com docs, never guess) over a CSS-gradient fallback. Cars = `HERO_CARS` array (transparent cut-out images in `img/hero/`, optional `make` slug → "Shop <Make> parts" button calling `setMakeFilter`); 0 = copy only, 2+ = auto-rotate. It replaced the moving offers strip (`#offers`), which is gone from the page. The stage is a **Gogoro-style showpiece**: each entry's `badge` — the **make** ('BMW'), not the model — is drawn huge and outlined behind the car, with the caption (which does carry the model, "BMW M4") in the bottom corner and the headline/buttons/trust row centred beneath. Set `badge` explicitly and keep it SHORT: it scales to fit its own viewBox, so 'MERCEDES-BENZ' would render short and weedy next to 'BMW' — hence 'MERCEDES'. The badge is inline SVG, not styled text, because `-webkit-text-stroke` only takes a flat colour and the outline carries a red→gold gradient. Adding a car = drop a cut-out in `img/hero/` and append one entry; nothing else changes. **Parts are advertised as CALLOUTS on the cars, not as slides of their own** (the two hand-drawn SVG part slides were rejected and deleted on 2026-11-10). Each entry carries a `callouts` array: a red dot pinned to the part, an **elbow** leader line (diagonal leg, corner, flat horizontal run) out into the black space, and a card with a product photo from `img/parts/`, the brand and the part name, wired to `jumpCat()`. Geometry is `{ x, y, dx, dy, run }` — x/y are percentages of the car image so the dot tracks the car; dx/dy are the label offset from the dot; `run` (default 70) is the flat leg. Keep right-hand cards clear of the next arrow at mid-stage. **Check placement in a screenshot, never with `getBoundingClientRect()`** — the stage has a 3D perspective transform and the rects come back 200-300px out. **Set `scale` on every entry** — the cut-outs range from 1.75:1 (Touareg) to 2.75:1 (911), so one shared CSS width would leave the SUVs towering over the sports cars and jolt the stage on each rotation; `scale` is a width multiplier that evens them out by HEIGHT instead (roughly aspect ÷ 2.2, the E-Class at `scale: 1`), fed to `.ge-car-tilt` as the `--scale` custom property. **Cut-outs only** — a photo that still has its background covers the lettering. The `--car` custom property that masks the sheen is built with `new URL(src, document.baseURI)` on purpose: a relative URL inside a custom property resolves against `code/css/`, not the page.

- **Image work without tooling**: there is no Python, no `sharp`/`canvas`, and node can't decode webp/jpg, so `logo.jpg` → icons, the share card, and the hero images were all produced in a **browser canvas** driven by the chrome-devtools MCP, with the page POSTing results to a throwaway node server that wrote them into the repo. All six current cars arrived already cut out, so processing is just crop-to-alpha-bbox → two WebP sizes, **never upscaling** (the Audi's source is only 612px wide, hence `w: 612`, and it is softer than the rest). Originals kept in `img/hero/src/`. If a future car comes in *with* a background: flood-fill from the border blocked by gradient magnitude + saturation — a plain colour-step fill leaks straight through glossy bodywork and erases the car — then opening → largest-blob → a brightness key over the bottom band for studio-floor leftovers.
- **Palette (red, not gold)**: graphite / white / grey surfaces with a single **red** accent taken from the logo. Tokens sit at the top of `code/css/01-base.css` and are mirrored in `admin/css/01-layout.css` and `404.html`'s inline `:root`. `--orange` `#c1121f` is the accent on LIGHT surfaces (6.2:1 on white, always carries **white** text); `--orange-light`/`--gold` `#ef3b42` is the brighter red for DARK surfaces (4.5:1 on `--bar`). ⚠️ **`--yellow` `#f59e0b` is a status colour (low stock / pending), NOT the accent** — it used to share gold's hex, and making it match the accent again would collide with error red. The site was gold until 2026-11-09; when porting an old snippet remember gold was a *light* colour, so anything using it as a background set dark text — red needs white text instead.

- **Images**: no product images are hosted in the repo. `expert_products.img_url` = plain http(s) links only (never base64 — fetched on every page load); uploaded photos live in `expert_photos`. Brand assets: **`logo.jpg`** is the real logo — the owner's circular crest, 520×520, a circle touching all four edges on a white JPEG background. Every slot that shows it sets `border-radius: 50%`, which clips exactly the white corners so it works on the dark header/footer as well as light pages; keep that rule on any new slot. Because the ring lettering is unreadable below ~100px, the header pairs the badge with the `.logo-text-fallback` wordmark, which is now always visible (not just `onerror`) and the `<img>` carries `alt=""` so the name isn't announced twice. The old placeholder wordmarks `logo.svg` / `logo-dark.svg` are unused but kept. **`favicon.png` (256², transparent corners), `apple-touch-icon.png` (180², white square) and `og-image.jpg` (1200×630 share card) are all generated from `logo.jpg`** — the favicon is the red GX monogram on the white disc with a slim grey ring, because the full crest's ring lettering turns to mush below ~100px. The old `favicon.svg` / `og-image.png` placeholders are deleted; every page links `favicon.png` + `apple-touch-icon.png`.

## Hard-won gotchas (inherited, still true)

- **CSS `url()` references are relative to the CSS file's own path** — moving a CSS file breaks `url('../…')` inside it. A `git mv` followed by an `Edit` does NOT re-stage the edit; check `git diff --cached` before committing.
- **PostgREST upsert (`on_conflict` + `resolution=ignore-duplicates`) fails under RLS when the role has no SELECT policy** (Postgres needs read visibility for `ON CONFLICT`). `offer_subscribers` is insert-only for anon on purpose: plain `INSERT`, treat `409` as "already subscribed".
- **Don't `git add -A` / `git add .`** — stage explicit paths.
- **`git push` to `main` can be rejected as diverged** because `generate-seo.yml` committed a regeneration. Recover with `git fetch && git merge origin/main --no-edit` (merge, not rebase), then push.
- **Category renames/reorders are cached to `localStorage`** (`cat_order_cache`, `cat_labels_cache`) so the page paints the saved state before Supabase answers. A new admin-editable category property should mirror this (write the cache on storefront load in `code/js/01-config-data.js` AND on save in `admin/js/05-categories.js`'s `saveCatChanges()`).
- **Never enter the admin panel password**, even if handed over — ask the owner to relay screens/values, or to run the account command themselves.
- **`create or replace function` does NOT replace a function whose parameter list changed** — the old overload keeps working. After any RPC signature change check `select proname, pg_get_function_identity_arguments(oid) from pg_proc where proname = '…'` and `drop` the old one.
- **New Postgres functions grant `EXECUTE` to `PUBLIC`**, which `anon` inherits — `revoke … from anon` alone isn't enough. `revoke … from public`, then grant to specific roles (see the privileges block in `supabase/schema.sql`).
- **`position: sticky` breaks if any ancestor has `overflow` other than `visible`/`clip`** — `html`/`body` use `overflow-x: clip` (with a `hidden` fallback line) in `code/css/01-base.css`. Don't change it back to `hidden`.
- **The homepage `<title>`/description are overridden at runtime** by `expert_settings.seo_settings` (`applySEOSettings()`). Update both the tags in `index.html` and that JSON (read-modify-write with `value::jsonb || jsonb_build_object(...)` so keywords survive).
- **Product page `<title>`s are de-duplicated by the generator** (`markDuplicateTitles()` appends the SKU) — don't hand-fix them.
- **Disabled on purpose (inherited from the fork) — restore together, don't half-restore:** (1) sort dropdown (`.sort-wrap { display: none !important; }` in `code/css/02-sections.css`); (2) Arabic toggle (`.lang-btn { display: none !important; }` in `code/css/06-lang-rtl.css`, `ARABIC_ENABLED = false` in `code/js/04-i18n-order.js`, and `hreflang="ar"` + `og:locale:alternate ar_AE` removed from `index.html`). Arabic strings are kept up to date for UAE.

## Workflow notes

- No Python on this machine — local preview with a small `node` static server that serves the repo under `/German-Expert/` (so root-relative paths in `404.html` work), e.g. port 8123.
- No test suite. Verify with the local server + browser console/network, then push, then `curl` the live Pages URLs (Pages + the SEO Action take a minute or two).
- One-off maintenance scripts go in `scripts/` — plain Node, no dependencies, built-in `fetch`/`fs`; give write scripts a `--dry-run` flag and run it first.
- GateGuard hooks ask for "facts" before first Bash/Edit calls; state them briefly and retry. The hook also blocks `rm` — delete with `node -e "require('fs').rmSync(path,{recursive:true,force:true})"`.
- Long bash heredocs / `node -e` with nested quotes tend to break in this shell; write one-off edit scripts with the Write tool (e.g. into `C:\Users\mukke\AppData\Local\Temp\ge-work\`) and run them with `node`. Make them fail loudly when an expected string isn't found.
- Edge-function JWT settings: **all five deploy with `verify_jwt: false`** (settled 2026-11-09, currently deployed that way). `notify-order`, `order-invoice` and `unsubscribe` are public by design. `admin-manage-accounts` and `send-offers` authenticate in-body instead — the former's `bootstrap` action must work with nobody logged in, and the latter's cron caller sends a static `x-admin-token`, not a JWT; turning platform JWT verification on would break both. Every other action in those two still resolves the caller's token and checks `expert_admin_profiles.role`.
- Admin accounts on a fresh project: POST `{"action":"bootstrap","accounts":[{username,password,role}]}` to `/functions/v1/admin-manage-accounts` (only works while `expert_admin_profiles` is empty). The OWNER runs it with their own passwords — Claude never picks or types them. Roles: `super` (owner), `bahar15` (manager), `1` (admin), `custom` (team).
