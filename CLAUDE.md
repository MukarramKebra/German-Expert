# German Expert — Project Notes

Static e-commerce site for **German Expert**, a German car-parts shop in Sharjah, UAE (Mercedes-Benz, BMW, Audi, VW, Porsche, MINI, Opel). Hosted on GitHub Pages at `https://mukarramkebra.github.io/German-Expert/` (repo `MukarramKebra/German-Expert`), backed by Supabase. No build step, no `package.json` — plain HTML/CSS/JS.

Forked on 2026-11-08 from the Expert Hardware Kuwait store (repo `MukarramKebra/Hardware-Website`, git remote `kuwait` here, Supabase `qhebhvllkovfbkqrcnmm`). That project is a separate live site — never write to it from here. Many internal identifiers still carry the fork's names on purpose (table prefix `expert_*`, localStorage keys `jain_*`/`bahar_*`, CSS token `--orange`); they're invisible to visitors and renaming them is pure churn.

## Architecture

- **Storefront**: `index.html`. CSS/JS are injected at runtime by two small loader IIFEs (near the top and bottom of `index.html`) that build `code/css/*.css?v=<version>` / `code/js/*.js?v=<version>` tags. The version comes from `localStorage.expert_asset_v`, synced against `expert_settings.asset_version` (bumped by the admin's "Flush Cache" button, not by git pushes).
- **Single config point**: top of `code/js/01-config-data.js` — `GE_SB_URL`, `GE_SB_KEY_B64` (base64 publishable key; the public key, not a secret), `SHOP_WA` (WhatsApp number used for every wa.me link), `SITE_URL`, `CURRENCY` + `fmtPrice()` / `roundMoney()` (AED, 2 decimals — every storefront price goes through `fmtPrice`). `scripts/generate-product-pages.js` parses `GE_SB_URL`/`GE_SB_KEY_B64` out of that file with a regex, so keep them simple string literals. Two other places hardcode the project and must be kept in sync: `admin/js/01-core-data.js` (`SB_URL`/`SB_KEY`) and `order-invoice.html` (`SB_URL`).
- **Admin panel**: `admin/index.html` + `admin/css/` + `admin/js/` — separate static app. `admin/index.html` has `<base href="../">`, so relative URLs resolve from the SITE ROOT (write `logo.svg`, never `../logo.svg`).
- **Product pages**: `/product/<slug>.html` + `sitemap.xml` are AUTO-GENERATED by `scripts/generate-product-pages.js` from live Supabase data via `.github/workflows/generate-seo.yml` (every push to `main` except pushes touching only `product/**`/`sitemap.xml`, plus nightly 03:17 UTC). Never hand-edit them. `MIN_PRODUCTS` defaults to 0 because the catalog starts empty — raise it (or set `SEO_MIN_PRODUCTS` in the workflow) once there's a real catalog, so an outage returning `[]` can't wipe the sitemap.
- **Backend**: Supabase project `qljcyiwkwdfodmabnzol`. **`supabase/schema.sql` is the source of truth** for every table, function, RLS policy and grant (rebuilt from the Kuwait live DB, not its stale SQL files). Tables: `expert_*` (catalog/site/orders/admin) and `offer_*` (email subscribers/campaigns). Any schema change: update `schema.sql` too.
- **Admin auth**: real Supabase Auth users. `doLogin()` in `admin/js/03-auth.js` derives `<username>@german-expert.internal` (`EMAIL_DOMAIN`, must match `supabase/functions/admin-manage-accounts`) and calls `/auth/v1/token?grant_type=password`. RLS on every admin-write table only allows `authenticated` + `is_admin(auth.uid())` (a row in `expert_admin_profiles`); anon can only `select`. Accounts are created/edited/deleted ONLY via the `admin-manage-accounts` Edge Function (service role). Its `bootstrap` action creates the first accounts and only works while `expert_admin_profiles` is empty. After login, `SB_HDRS.Authorization` (`admin/js/01-core-data.js`) is mutated in place to the user's token — that's what authenticates every admin write. Checkout stock deduction uses the `decrement_stock` RPC (anon-callable, can only subtract).
- **Edge functions** (`supabase/functions/`): `admin-manage-accounts`, `notify-order` + `order-invoice` (deploy with JWT verification OFF), `send-offers`, `unsubscribe`. Email goes through Resend — needs `RESEND_API_KEY`; `OWNER_EMAIL` / `FROM_EMAIL` secrets override the placeholder addresses. The send-offers cron token lives in `expert_service_secrets` (key `send_offers_cron_token`).
- **Hero showcase**: `#showcase` (top of `index.html`) = `code/js/08-hero.js` + `code/css/10-hero.css`. Background is a WebGPU shader (`shaders@4.0.5` via jsDelivr ESM, `HERO_SHADER_PRESET`; check prop names against `~/.claude/skills/shaders/components.md` / shaders.com docs, never guess) over a CSS-gradient fallback. Cars = `HERO_CARS` array (transparent cut-out images in `img/hero/`, optional `make` slug → "Shop <Make> parts" button calling `setMakeFilter`); 0 = copy only, 2+ = auto-rotate. It replaced the moving offers strip (`#offers`), which is gone from the page. The stage is a **Gogoro-style showpiece**: each entry's `badge` — the **make** ('BMW'), not the model — is drawn huge and outlined behind the car, with the caption (which does carry the model, "BMW M4") in the bottom corner and the headline/buttons/trust row centred beneath. Set `badge` explicitly and keep it SHORT: it scales to fit its own viewBox, so 'MERCEDES-BENZ' would render short and weedy next to 'BMW' — hence 'MERCEDES'. The badge is inline SVG, not styled text, because `-webkit-text-stroke` only takes a flat colour and the outline carries a red→gold gradient. Adding a car = drop a cut-out in `img/hero/` and append one entry; nothing else changes. **Only the first slide loads with the page** — the rest are stacked at `opacity: 0` *inside* the viewport, where `loading="lazy"` does nothing, so they carry `data-src`/`data-srcset` and `hydrate()` turns each on one slide ahead of the rotation. `sizes` carries a deliberate **DPR cap** (`(max-width: 600px) 240px`) so a 3x phone resolves the 760w `-sm` copy (~46 KB) instead of the 1400w one (~113 KB); the `<link rel=preload>` in `index.html` repeats that `sizes` list and **must stay character-identical**. The sheen's `--car` mask is set by `paintMask()` from `img.currentSrc` after load, never hardcoded — hardcoding it made the mask a second, independent fetch of the full-size file at every DPR. **Parts are advertised as a ROTATING RING of spare parts around each car** (2026-11-13, replacing the two static elbow callouts per car, which replaced two hand-drawn SVG part slides on 2026-11-10 — this surface has been reworked twice, so check the code before trusting an older note). `HERO_PARTS` in `08-hero.js` is ONE shared list of EIGHT parts (2026-11-14) — brand, part name, `cat`, and an `img` from `img/parts/` (a Font Awesome `icon` is still supported but none use it: without a disc a red glyph vanished into the red make badge) — because the catalogue is the same whichever car is on stage; a car may override it with its own `parts` array. Each item is a button wired to `jumpCat()`. **Parts render in their OWN shape, never in a circle** (owner, 2026-11-14): `.ge-ring-img` is `object-fit: contain` with no border/background/radius, lifted off the dark stage by `drop-shadow()` filters (a `box-shadow` would outline the transparent PNG's rectangle). Ring photos must be transparent cut-outs, cropped to the part, 320px max. **TEN is the ceiling for this ellipse**: a flat ring bunches its items at the left and right extremes, and at twelve the 30° spacing left ~63px between neighbours against a 136px chip, so the brand lines overlapped. **The motion is one registered `@property --ge-orbit` animated on the parent and inherited**, so ten chips can never drift out of step; each derives `--a: calc(var(--ge-orbit) + (360deg / var(--n)) * var(--i))` and is placed by a **pure translate** onto the ellipse via `cos()`/`sin()` — no rotation anywhere, so nothing needs counter-rotating. `--d: calc((sin(var(--a)) + 1) / 2)` drives scale, opacity and `z-index`, which is what sells the depth. ⚠️ **The ring is exempted by name from the low-GPU profile.** The inline `<style id="ge-low-gpu-mode">` in `index.html` carries `.ge-hero *:not(.ge-ring) { animation: none !important }` — without the `:not()` the ring renders frozen with no error anywhere to say why (that block is also why the car float is `geLowGpuCarFloat`, not `geCarFloat`). **The parts orbit OUTSIDE the prev/next arrows** (owner, 2026-11-14), and the ring could NOT simply grow to do it — at 1280px a part sitting at the stage edge already hangs off the viewport. **The arrows moved inboard instead**, to `left/right: 16%`, into the gap between the car and the ring, so the order outward is car -> arrow -> part. 16% is the one value that holds at both ends: further out and the ring catches them at 1280px, further in and they touch the widest car (the Touareg, `scale: 1.15`). They go back to the stage edges below 1025px, where the ring is hidden. **The radii are squeezed from both sides**: `--rx: clamp(190px, 41vw, 596px)` has to clear the car (itself `min(55%, 610px)`, so at 1100px a smaller ring surfaced labels inside the bodywork) and now also clear the arrows, while the VIEWPORT caps the far end; `--ry: clamp(92px, 16.4vw, 222px)` has to beat half the car's height yet stay inside the stage, which is 52vw and shrinks faster — at 20vw the bottom chips landed on the caption and the slide dots. `.ge-car-cap` gets a `closest-side` radial scrim so the arc sweeping through that corner reads as depth, not as a clipped chip (**any radius over 50% leaves a grey panel with four hard edges**). **`.ge-ring` is `inset: 0 0 84px 0`, not `inset: 0`** — reserving space at the bottom lifts the whole orbit, which is what keeps the lower arc off the model caption now that the parts are bigger (face `clamp(104px, 10.6vw, 152px)`, image `clamp(82px, 8.4vw, 122px)`). There is headroom above to pay for it; the top arc still clears the header by ~48px at 1440. **A 1025-1199px band shrinks the car AND the parts** (`min(50%, 540px)`, arrows at 13%): three things are squeezed at once there — the viewport caps how far out a part can sit, the car is sized off that same viewport, and the arrows must fit between them — and without it the arrows land on the bodywork at 1100px. That block sits BELOW the `.ge-car-nav` rules on purpose: same specificity, so source order decides. ⚠️ **Measure the ring, never the car** — `.ge-car-tilt` lives inside the stage's `perspective: 1400px` subtree, so its `getBoundingClientRect()` is hundreds of px out (a `scale: 1.15` car measured 513px wide instead of 701). The ring is a sibling of the tilt, so ITS rects are honest; check car clearance from a screenshot. **At ≤1024 the ring is `display: none`** and `.ge-car-chips` takes over: the same ten parts as a horizontal scroll strip under the car. It is a strip, not a justified row — `flex: 1 1 0` divided 390px by ten and gave each chip 39px, which wrapped every label into one-character columns stacked over the car — and it is safe to scroll because the hero has nav arrows and no swipe handler of its own. The nav arrows sit at `top: 24%` in that band, left over from the pins that collided with them on the E-Class, Touareg and Range Rover. **Set `scale` on every entry** — the cut-outs range from 1.75:1 (Touareg) to 2.75:1 (911), so one shared CSS width would leave the SUVs towering over the sports cars and jolt the stage on each rotation; `scale` is a width multiplier that evens them out by HEIGHT instead (roughly aspect ÷ 2.2, the E-Class at `scale: 1`), fed to `.ge-car-tilt` as the `--scale` custom property. **Cut-outs only** — a photo that still has its background covers the lettering. The `--car` custom property that masks the sheen is built with `new URL(src, document.baseURI)` on purpose: a relative URL inside a custom property resolves against `code/css/`, not the page.

- **Image work without tooling**: there is no Python, no `sharp`/`canvas`, and node can't decode webp/jpg, so `logo.jpg` → icons, the share card, and the hero images were all produced in a **browser canvas** driven by the chrome-devtools MCP, with the page POSTing results to a throwaway node server that wrote them into the repo. All six current cars arrived already cut out, so processing is just crop-to-alpha-bbox → two WebP sizes, **never upscaling** (the Audi's source is only 612px wide, hence `w: 612`, and it is softer than the rest). Originals kept in `img/hero/src/`. If a future car comes in *with* a background: flood-fill from the border blocked by gradient magnitude + saturation — a plain colour-step fill leaks straight through glossy bodywork and erases the car — then opening → largest-blob → a brightness key over the bottom band for studio-floor leftovers.
- **Palette (red, not gold)**: graphite / white / grey surfaces with a single **red** accent taken from the logo. Tokens sit at the top of `code/css/01-base.css` and are mirrored in `admin/css/01-layout.css` and `404.html`'s inline `:root`. `--orange` `#c1121f` is the accent on LIGHT surfaces (6.2:1 on white, always carries **white** text); `--orange-light`/`--gold` `#ef3b42` is the brighter red for DARK surfaces (4.5:1 on `--bar`). ⚠️ **`--yellow` `#f59e0b` is a status colour (low stock / pending), NOT the accent** — it used to share gold's hex, and making it match the accent again would collide with error red. The site was gold until 2026-11-09; when porting an old snippet remember gold was a *light* colour, so anything using it as a background set dark text — red needs white text instead.

- **Images**: no product images are hosted in the repo. `expert_products.img_url` = plain http(s) links only (never base64 — fetched on every page load); uploaded photos live in `expert_photos`. Brand assets: **`logo.jpg`** is the real logo — the owner's circular crest, 520×520, a circle touching all four edges on a white JPEG background. Every slot that shows it sets `border-radius: 50%`, which clips exactly the white corners so it works on the dark header/footer as well as light pages; keep that rule on any new slot. Because the ring lettering is unreadable below ~100px, the header pairs the badge with the `.logo-text-fallback` wordmark, which is now always visible (not just `onerror`) and the `<img>` carries `alt=""` so the name isn't announced twice. The old placeholder wordmarks `logo.svg` / `logo-dark.svg` are unused but kept. **`favicon.png` (256², transparent corners), `apple-touch-icon.png` (180², white square) and `og-image.jpg` (1200×630 share card) are all generated from `logo.jpg`** — the favicon is the red GX monogram on the white disc with a slim grey ring, because the full crest's ring lettering turns to mush below ~100px. The old `favicon.svg` / `og-image.png` placeholders are deleted; every page links `favicon.png` + `apple-touch-icon.png`.

- ⚠️ **The collage is a PINWHEEL, not an even 2×2 cross — never lay an even grid over it.** The two top photos meet at x=44.1%, the two bottom ones at x=65.2%, the left column splits at y=50.8% and the right at y=58.9%. An even quartering put each label's shading partly on its neighbour's photo. Each label therefore carries its own `box: [left, top, width, height]` in percent, measured by scanning the source for the strongest luminance discontinuity inside each expected band (the brightest-column trick finds sky and signage, not seams, and there are no white gutters). **Re-measure the same way if the picture is ever replaced — don't eyeball it.** A row with no boxes falls back to `EVEN_BOXES`, which is wrong for this picture but the only sane guess for an unmeasured one.
- **A box that stops short of the bottom of the picture gets `.is-mid`** — its scrim fades back out instead of ending in a hard horizontal step across the middle of its own photo (the top-right box ends at 50.8% but its photo runs to 58.9%). `.is-mid` also takes a deeper bottom padding so the text still sits in the dark part.

- **`sub` is hidden below 860px** — a quarter of a phone-width 16:9 picture is about 190×105, and only the name fits. The name is the part that says what we do, so it stays at every size.

## Hard-won gotchas (inherited, still true)

- **CSS `url()` references are relative to the CSS file's own path** — moving a CSS file breaks `url('../…')` inside it. A `git mv` followed by an `Edit` does NOT re-stage the edit; check `git diff --cached` before committing.
- **PostgREST upsert (`on_conflict` + `resolution=ignore-duplicates`) fails under RLS when the role has no SELECT policy** (Postgres needs read visibility for `ON CONFLICT`). `offer_subscribers` is insert-only for anon on purpose: plain `INSERT`, treat `409` as "already subscribed".
- **Don't `git add -A` / `git add .`** — stage explicit paths.
- **`git push` to `main` can be rejected as diverged** because `generate-seo.yml` committed a regeneration. Recover with `git fetch && git merge origin/main --no-edit` (merge, not rebase), then push.
- **Category renames/reorders are cached to `localStorage`** (`cat_order_cache`, `cat_labels_cache`) so the page paints the saved state before Supabase answers. A new admin-editable category property should mirror this (write the cache on storefront load in `code/js/01-config-data.js` AND on save in `admin/js/05-categories.js`'s `saveCatChanges()`).
- **Never enter the admin panel password**, even if handed over — ask the owner to relay screens/values, or to run the account command themselves.
- **`create or replace function` does NOT replace a function whose parameter list changed** — the old overload keeps working. After any RPC signature change check `select proname, pg_get_function_identity_arguments(oid) from pg_proc where proname = '…'` and `drop` the old one.
- **New Postgres functions grant `EXECUTE` to `PUBLIC`**, which `anon` inherits — `revoke … from anon` alone isn't enough. `revoke … from public`, then grant to specific roles (see the privileges block in `supabase/schema.sql`).
- **`position: sticky` breaks if any ancestor has `overflow` other than `visible`/`clip`** — `html`/`body` use `overflow-x: clip` (with a `hidden` fallback line) in `code/css/01-base.css`. Don't change it back to `hidden`.
- **The homepage `<title>`/description are overridden at runtime** by `expert_settings.seo_settings` (`applySEOSettings()`). Update both the tags in `index.html` and that JSON (read-modify-write with `value::jsonb || jsonb_build_object(...)` so keywords survive).
- **Product page `<title>`s are de-duplicated by the generator** (`markDuplicateTitles()` appends the SKU) — don't hand-fix them.
- **Never put `scroll-behavior: smooth` back on `html`** (`code/css/01-base.css`). On an element it animates EVERY scroll, the mouse wheel included, which is what made the owner report the site "feels capped at 30fps" on 2026-11-11 — it was never dropped frames (165fps measured, zero frames >20ms). Smooth anchor scrolling now lives in the delegated handler in `code/js/06-features.js`, which gates on **`e.defaultPrevented`**, not on "has an onclick": every main nav link has an onclick that merely closes the mobile drawer.
- **The hero shader must be paused when off screen.** `.is-idle` only pauses CSS animations; a `shaders@4.0.5` instance keeps drawing full-screen at the display's refresh rate until you call `pause()`. `08-hero.js` retains the instance and exposes `window._geHeroShaderRunning(run)`, driven by the stage's IntersectionObserver and `visibilitychange`.
- **The red scrolling brand strip is GONE, not hidden** (2026-11-13). `.marquee-wrap` sat under the hero scrolling `Mercedes-Benz · BMW · Audi …`; the owner asked for it removed (*"u see the read strip moving remove that"*), so the markup, the `.marquee-*` rules in `01-base.css` and `fillMarquee()` + its language-switch rebuild in `04-i18n-order.js` were all deleted. `@keyframes marquee` stays because the (already dead) `.offers-track` rules still name it. The hero's bottom `::after` fade was written to blend INTO that bar — it now fades into the category grid, which is fine, but that's why the comment changed.
- **Disabled on purpose (inherited from the fork) — restore together, don't half-restore:** (1) sort dropdown (`.sort-wrap { display: none !important; }` in `code/css/02-sections.css`); (2) Arabic toggle (`.lang-btn { display: none !important; }` in `code/css/06-lang-rtl.css`, `ARABIC_ENABLED = false` in `code/js/04-i18n-order.js`, and `hreflang="ar"` + `og:locale:alternate ar_AE` removed from `index.html`).
